# EF Harness: architecture

A desktop coding harness for developers. It interviews you until it understands the whole project, turns that into research, architecture and a task plan stored in one versioned knowledge database, then builds the app with a team of AI workers in isolated Git worktrees. Every piece of work is checked by an independent verifier before it is merged, and you can watch and steer the whole build.

**Status:** design phase. No code yet. These documents are the proposed architecture; the [roadmap](roadmap.md) says what gets built first.

## The pattern in one paragraph

This is not a free-form “agents chatting with agents” system. A deterministic **kernel** (TypeScript, sole writer of a SQLite database) owns all state, budgets, permissions and Git branches. **Planners** (Manager and Senior models) propose decisions, architecture, plans and integrations as typed actions the kernel validates. **Workers** (Junior to Senior models, or another company's agent such as Codex or Claude Code) lease one task at a time with a self-contained brief and a narrow write scope. A **clean verifier** accepts work only from checks written before the code. Agents never trust each other's words; they exchange versioned artifacts.

## Why the branches do not fit together

About 30% of the defects are inside one worktree: the code does not do what its own task section and the design documents require, even before it meets anything else. Fix those while that branch is landing.

About 70% appear only when worktrees meet. The worker finished its own goal. It did not see the other worktree. Expect these seams, and look for them rather than waiting for the compiler to list them:

- **Shadow ports.** The task declared a local TypeScript interface for a neighbor it was not allowed to import yet (`CoordinatorWriteQueue`, `OutboxRepo`, `ReadModelRepo`, `ProtocolConnection`, `KnowledgeGraphRepo`, `BudgetLedger`, and many others). The real type now lives, or will live, in another package. Names, methods, argument order, and return shapes differ. The combination edit deletes the local copy and imports the real export. Where the shapes differ, the architecture's contract wins, then the signature already on `harness/integration` if the producer task is already merged. Do not keep both types. Do not average them.
- **Barrels that were never edited.** Exports stop at a subpath `index.ts` such as `packages/ipc/src/protocol/index.ts`. The package root `src/index.ts` does not re-export them. Handoff "Shared Wiring Needs" is the request. Apply it. Consumers must import `@ef-harness/<id>`, not a deep file inside another package.
- **Dependencies that were never added.** The import works inside the task worktree only because Node walks up to the root `node_modules`. `package.json` of that package never listed it. Add the dependency intent to the owning package, then update `pnpm-lock.yaml` once for the wave with `pnpm install`. Reconcile version ranges before installing. Conflicting ranges are a BLOCKER, not a guess.
- **Layer violations.** `scripts/layers.mjs` is the map. A package may import only a strictly lower layer, and only through that package's barrel. Layer 0: `shared-contracts`, `shared-observability`. Layer 1: `db`, `ipc`, `sim`, `git-engine`, `sandbox`, `mcp-server`, `test-env`. Layer 2: `worker-loop`, `completeness-gate`, `verifier`, `discovery`, `spec-expansion`, `research-engine`, `intake`, `dictation`, `brownfield`. Layer 3: `planner`, `integrator`, `steering`, `governor`, `providers`, `runtime-adapters`. Layer 4: `ship-deploy`, `investigations`, `portability`, `meta-lab`. Layer 5 apps and tools: `apps/daemon`, `apps/desktop`, `apps/renderer`, `spikes`, `corpus`, `benchmarks`, `tests/e2e`. Same-layer imports and upward imports are seams. Fix them by moving the shared type down to `shared-contracts` or by injecting a port that the lower layer already owns. Do not "fix" a layer break by editing `layers.mjs` unless the design documents changed the layout.
- **TypeScript settings that isolation hid.** `tsconfig.base.json` uses `NodeNext`, `verbatimModuleSyntax`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, and `strict`. Relative imports need the `.js` suffix even though the source is `.ts`. Type-only imports must be `import type` or `export type`. Passing an explicit `undefined` into an optional property is a type error. A test file inside one package never compiled the other package's barrel, so these errors show up at the first real project-reference build.
- **Tests that mock the neighbor.** A passing `pnpm --filter @ef-harness/<id> test` does not mean the join works. Where the architecture says package A calls package B, the combination check imports the real barrel. Keep a mock only where the design says the boundary is a fake (the deterministic model stub, the sandbox double, the sim harness).
- **Shared files both sides touched.** Root and package manifests, lockfile, barrels, route tables, IPC method registries, Electron handler lists, and `apps/renderer` route maps. Workers were forbidden to edit these, but some did. Diff those paths across every unmerged branch before choosing a wave. The integration copy is the base. A task may add its own lines. It may not revert a barrel export or a dependency that an earlier integrate commit added.
- **Schema and vocabulary drift.** Workers were forbidden to edit `schema/**`. A contract-change request that needs new SQL is not applied by silently editing `state.sql` inside the merge. Either the design documents already contain that SQL and a task violated scope by not being the schema owner, or the request is a BLOCKER. `node schema/schema-test.js` must keep reporting `67/67 passed` unless a combination task quotes the design change that adds scenarios, and then it updates the test in the same task. Closed vocabularies are part of the contract: settled basis is only `explicit`, `derived`, `delegated`, `defaulted`, `proposed`, `observed`. Criterion status is only `open`, `partial`, `missing`, `conflict`, `asked`, `deferred`, `not_applicable`, `settled`. `HELD` is not a task state. Holds are rows, so clearing one reason must not clear another. Money and allowances are integers at scale `1000000`. Timestamps are UTC integer milliseconds. Content hashes are SHA-256 over RFC 8785 canonical JSON of `{kind, title, text, fields}` with NFC strings. Never `ATTACH` two WAL databases in one write transaction. Mutating IPC methods require a non-empty `op_id`.
- **Spikes are evidence.** Tasks 002–006 record measurements. Production packages must not import `spikes/**`. If a later task copied spike code instead of calling the package that was supposed to absorb the verdict, that copy is a local defect.
- **Two writers of one product concept.** Intake, planner, integrator, renderer, and daemon each grow registrations. A method, event, route, or IPC name invented in two unmerged tasks is one seam, even if both compile alone.
- **Milestone gates that pass on a stub.** Tasks 105 (M2), 134 (M3), 152 (M4), 175 (M5), 195, and 200 (M6) are proofs of the tasks they depend on. Landing a gate before its inputs, or leaving the gate talking to shadow ports, is a failed wave. Task 034 (M0) and Task 068 (M1) are already on integration. Do not weaken their checks to make a later merge pass.

Provider and security rules are behavior, not style. Claude is Console API key only. No subscription OAuth and no `claude setup-token`. Gemini CLI stays off unless the policy warning is explicit, and nothing reads `~/.gemini`. Antigravity is never offered. No silent fallback from a plan to paid API credits. Coding workers have no direct internet. Dependencies are installed by the maintainer with pnpm, not by a worker script. Do not let a merge reintroduce any of those paths. `scripts/harmony-lib.mjs` already rejects the forbidden compliance strings and secret markers.
